# Retichess

## What?
The aim is for this to be a multiplayer chess program, with a TUI built using Textual, which uses Reticulum as its transport method.

## Initial commit
As of writing, 23/07/2026 0200, there is nothing finished here.

Current features:
- Digital board representation
- Pawn movement logic (not including En Passant)
- Knight movement logic
- King movement logic
- The underlying logic which confirms the legality of a potential move

## What to expect
God only knows to be quite honest. If you couldn't tell I'm not a terribly experienced developer and this is my first time using Python in my life (no seriously, I am learning so much on the fly. ADHD is a powerful and dangerous curse).

I have a pretty clear mental model of how I want the program to work and am focused on building the chess logic part within that model. Once I'm comfortable that Chess exists within the lines of code, then I'll start work on the UI to present it. I think last will be implementing the networking side of things because as cleas as my mental model is, my actual knowledge of networking and developing with Reticulum are shaky at best.

I will also focus on this README and documentation to hopefully explain my thought process behind the model and how it works. I'm not doing this to write an efficient or competitive chess program; there will be no timers, or chess engines, or score (initially, still TBD). The joy of chess for me is not represented by speed or score, which is not to say that they're not important to the community but only to explain why they're not my focus in the development of this program. 

As I get more comfortable in development who's to say? Some features might appear that where hitherto not on the horizon. However it's important to set expectations and my ambitions at the start.
